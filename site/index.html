Jev recipes is an open-source TypeScript library for routing requests, reranking evidence, and reviewing agent actions. Each recipe returns a typed decision with explicit uncertainty. This is a library for one bounded decision at a time: your application keeps control of tools, permissions, and business state.

How do I use Jev recipes in TypeScript?

Install the package, import a recipe, and handle its typed result. The package is an ES module library for Node.js 22.9 or newer, as stated in the installation guide [1]. A recipe refers to a small function that asks Jev one bounded question and validates the response.

Install Jev recipes and run a saved example

npm install jev-recipes
npx jev-recipes demo route

The demo is an offline contract example, not a live accuracy test. It needs no API key because it replays a hand-authored response. A fixture is defined as the saved input and response used to demonstrate that contract. According to the getting-started examples [2], your application needs to handle ready decisions, review decisions, and provider failures separately.

TypeScript inputs and result types

For a new TypeScript project, install the compiler and Node.js type definitions:

npm install --save-dev typescript @types/node

TypeScript infers each recipe's input and result from its exported schemas. Use RouteInput and RouteResult when your TypeScript application needs named types for the route recipe. Runtime validation still runs because static types do not validate incoming data. The route module exports the schemas and types together [3].

Call a recipe from TypeScript

Set TYPESAFE_API_KEY in the server environment before running this code. Live calls send the supplied input to TypeSafe and use API quota. 

import { route } from 'jev-recipes/route';

try {
  const result = await route({
    request: 'Please correct a duplicate charge.',
    routes: {
      billing: 'Payments, invoices, and refunds',
      technical: 'Errors, outages, and integrations',
    },
    minConfidence: 0.8,
  });
  if (result.status === 'ready') {
    console.log('Selected handler:', result.route);
  } else {
    console.log('Review required:', result.suggestedRoute);
  }
} catch (error) {
  console.error('Decision failed:', error);
}

The result is a validated decision, not an executed action. Keep dispatch and access checks in your application. The package uses Zod schemas to validate inputs and outputs; the route implementation [3] shows both checks.

How do I route support requests with Jev?

Use the route recipe with the request and a map of handler names to descriptions. The handler is the label your application uses to dispatch work. A ready decision means that the route passed the configured confidence policy. A review decision means that the recipe withheld automatic selection.

According to the route implementation [3], the default threshold is 80%. A reserved review choice also requires review, regardless of confidence. Confidence refers to the model's reported decision confidence, not a measured accuracy rate.

How confidence changes the saved routing result

The saved example reports 90% confidence for the billing route. The table applies the recipe's policy to that same response at seven thresholds. At 80%, it is ready; at 100%, it goes to review. These are policy settings and fixture results, not success-rate claims. The data comes from the saved route fixture [4].

How do I rerank evidence with Jev?

Pass a query and retrieved passages to the rerank recipe. The ranking is based on relevance to that query. Reranking refers to selecting and ordering supplied passages after retrieval. It does not fetch new documents or prove that a passage is true.

According to the rerank guide [5], passage IDs stay attached to selected items. This means that your application retains the source reference when it selects evidence. Use topK to cap the output and minRelevance to set the minimum score. Inspect the guide's contract and limitations before using the result.

How do I evaluate Jev recipe accuracy?

Run the evaluator on labeled cases from your workflow, save the responses, and compare the returned decisions with the labels. The evaluator is included in the installed package. According to the evaluation guide [6], overall accuracy includes failed cases in its denominator. Review rate and ready-decision accuracy answer different questions. 

npx jev-recipes evaluate route --cases ./routing-cases.jsonl --out ./results/baseline
npx jev-recipes replay ./results/baseline --min-confidence 0.9 --out ./results/review-at-90
npx jev-recipes compare ./results/baseline ./results/review-at-90

A held-out split refers to cases reserved for evaluation after the policy is chosen. Keep related case families in the same split because near-duplicate examples do not provide independent evidence. Saved fixtures and synthetic case scores do not establish performance on your production data. Earlier recipe or evaluator measurements remain labeled as earlier evidence.

Why replay the confidence policy?

Replay reuses retained responses without another model call. This is a way to compare review rates under different thresholds while holding the observed responses fixed. A new live evaluation is still needed to measure a changed model or recipe.

Connect Jev recipes to your workflow

The integration guide describes direct TypeSafe API access and Vercel AI Gateway access. According to that integration contract [7], both use the System One request format. Transport compatibility does not establish model accuracy. The same guide explains client injection and cancellation.

Use the npm package in your Node.js backend or a script. Inspect source and report issues on GitHub. For a working music example, visit Jevthoven above; its playback requires sign-in.

Key takeaways

  • Choose a recipe for one decision, and inspect its input and result contract.
  • Run a saved fixture first, then connect TypeSafe for live calls.
  • Keep review handling, permissions, and dispatch in your application.
  • Measure accuracy on your own cases before relying on a decision.

In summary, Jev recipes supplies typed decisions and inspectable evidence. Your code owns what happens next.
