# Project name

Replace these prompts with your project's details. This template is optional. Submit `examples/your-project/README.md`; adding a folder does not deploy an application.

## Try it

Describe what people can do. Link to a hosted app and public source when available. State sign-in, payment, and browser requirements. Credit the owner and disclose whether this is a maintainer-built or independent project.

## What Jev decides

Name the exact recipes and tested package version. Show one real input and its structured output. Explain why the decision needs judgment and where ordinary code takes over. State what ready, review, cancellation, and provider failure mean for the user.

## Run it

Give installation and run commands, Node/framework requirements, provider/model IDs, and placeholder environment variable names. Keep credentials server-side. Describe offline fixture mode separately from live calls. Keep framework dependencies in the example's own manifest and lockfile.

## Verify it

Link to tests and retained responses where shareable. Identify the date, input/label provenance, development and held-out separation, policy, and limitations. Fixture success establishes behavior, not accuracy. Label experiments as experiments and avoid adoption or savings claims without measurements.

## Ownership

Name the maintainer and support location. Explain who hosts the app and maintains dependencies. Include only code, data, and assets you have permission to share. Link back to the recipe source and [example guide](README.md).
